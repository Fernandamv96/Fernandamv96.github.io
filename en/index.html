JAVA · REST API

Clinic: patient records API

The problem
Keeping patients and medical histories in spreadsheets exposes sensitive data and gives no control over who can read or change each record.
The solution
A REST API with authentication, three roles (admin, doctor and reception) and Chilean RUT validation: reception registers patients, doctors write the medical history and only admins manage users.

Stack:

  • Java 21
  • Spring Boot
  • PostgreSQL
  • Docker
How I built it

How I used each technology

Spring Boot 3
Layered structure (controller → service → repository), DTOs and a global exception handler with consistent responses.
Spring Security + JWT
Login returns a token and every endpoint requires a role through @PreAuthorize; passwords are stored with BCrypt.
PostgreSQL + Flyway
The schema lives in versioned migrations (tables, indexes and development data), so the database is rebuilt identically in any environment.
Spring Data JPA
Paginated patient search by RUT, name or email without hand-written SQL.
Docker Compose
Starts the API and PostgreSQL with one command; multi-stage image with a non-root user, and Compose stops if a secret is missing.
JUnit 5 + Mockito
22 tests: RUT validator, patient service and a security regression test.
SpringDoc OpenAPI
Swagger UI to document and try every endpoint.

Decisions & security

  • I found that user registration was public and let anyone create an ADMIN account: now only an admin can register users, backed by a test.
  • No default credentials or JWT secret: everything is read from environment variables (.env.example).
  • The initial admin is created from an environment variable and its password is no longer printed in the logs.

CI with mvn verify, Docker build and CodeQL.

PYTHON · WEB

MediForm

The problem
On a paper visit form, fields are left blank, abnormal vital signs go unnoticed and finding a previous visit takes time.
The solution
A sectioned clinical form validated on both client and server, with alerts when a vital sign is out of range, automatic age and BMI calculation, and search by name or ID number.

Stack:

  • Python
  • Flask
  • SQLite
  • pytest
How I built it

How I used each technology

Flask + Jinja2
Routes, templates and custom filters (age, BMI and vital-sign status) used directly in the HTML.
SQLite
Serverless persistence; every query is parameterized with ?.
Flask-WTF
CSRF protection on every form that submits data.
Vanilla JavaScript
Live validation and delete confirmation without inline scripts, compatible with a strict CSP.
pytest
19 tests: creating visits, required fields, rejecting requests without a CSRF token, security headers and configuration.
gunicorn
Production server for deployment (Procfile).

Decisions & security

  • Debug off by default and server bound to 127.0.0.1: debug=True on 0.0.0.0 exposes the Werkzeug console to the network.
  • The app refuses to start in production without a SECRET_KEY.
  • CSP, X-Frame-Options, X-Content-Type-Options and Referrer-Policy headers on every response.
  • Educational project: not intended for real clinical data.

CI with ruff and pytest on Python 3.10 and 3.12, plus CodeQL.

CYBERSEC · CIA

CIA Audit

The problem
How do you stop a student from seeing other students' sensitive data, changing their own grades, or losing exam week to a system outage?
The solution
A simulation of controls for each CIA principle applied to INACAP's systems, in Python and as an interactive HTML simulator.

Stack:

  • Python
  • hashlib
  • HTML
  • pytest
How I built it

How I used each technology

Python (standard library)
One class per principle: role-based access control with an audit log, grade integrity, and the impact of a DDoS with a continuity plan.
hashlib (SHA-256)
A hash per academic record detects any change made outside the system; unauthorized changes are rolled back.
HTML + JavaScript
Interactive version to try roles and resources from the browser.
pytest + ruff
16 tests and linting with security rules (bandit) in CI.

Decisions & security

  • Tests revealed that access control allowed unknown resources (fail-open); it now denies by default.
  • An unkeyed hash detects accidental changes, but against an attacker you need an HMAC: documented as a next step.

CI with ruff, pytest and a full run of the simulation.

FULL STACK · REACT

TechStore Manager

The problem
A tech store managed its inventory by hand, with no quick view of stock, total value or products to restock.
The solution
A full-stack system with a REST API for product CRUD and a React dashboard with real-time inventory metrics.

Stack:

  • React
  • Express
  • Axios
  • Vercel
How I built it

How I used each technology

Express
REST API split into routes, controllers and middleware; server-side validation (name, category, price > 0, stock ≥ 0) is the source of truth.
Custom middleware
A logger records the method, path and time of every request.
React
Components (form, table, stats, notifications) with useState, useMemo for the metrics and useCallback for handlers.
Axios
A services/api.js layer centralizes requests and turns errors into readable messages for the user.
Vercel
Frontend and API deployed together: rewrites route /productos to a serverless function that reuses the Express app.
node:test
6 API tests with no extra dependencies: full CRUD, validation, malformed JSON and headers.

Decisions & security

  • CORS can be restricted with the FRONTEND_URL variable, and the X-Powered-By header is gone.
  • The error handler no longer returns err.message to the client in production.
  • listen() only runs when the server is started directly, so the app can be tested.

CI with backend tests, frontend ESLint and build, plus CodeQL.

PYTHON · DJANGO

Pharmacy Catalog

The problem
In a pharmacy, expired or soon-to-expire products are caught too late when the inventory lives in a spreadsheet.
The solution
A Django CRUD that shows the inventory value, flags products expiring within 30 days or already expired, and rejects products with a past expiration date.

Stack:

  • Python
  • Django
  • SQLite / PostgreSQL
  • Vercel
How I built it

How I used each technology

Django (generic views)
ListView, CreateView, UpdateView and DeleteView cover the CRUD; the list view computes the inventory metrics.
Django Forms
clean_fecha_vencimiento rejects past dates before saving.
ORM + migrations
SQLite locally and PostgreSQL through DATABASE_URL in production, with no code changes.
WhiteNoise
Serves static files (including the admin) in the serverless environment.
Vercel
On startup, migrations run and the superuser is created from environment variables.
Django tests
Listing, creation, deletion and rejection of expired dates.

Decisions & security

  • SECRET_KEY is required in production: before, if it was missing, an insecure key was used.
  • Secure cookies, HSTS and Referrer-Policy when DEBUG is off; CI runs manage.py check --deploy.

CI with ruff, Django tests and deployment checks, plus CodeQL.
